# Changelog

All notable changes to `ratada` are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html) – while `0.x`, a minor bump may contain breaking changes.

## [Unreleased]

## [0.8.0] - 2026-11-07

### Changed (breaking)

- **`form::Form` follows the form rules of the style guide.** It opens in normal mode, where letters are commands: `Enter` edits a text field (or toggles a checkbox, opens a date's calendar), `←`/`→` step a choice, `s` saves, `y` copies the focused value, `↑`/`↓` and `j`/`k` move the focus. While a field is edited, letters type; `Enter` (single line) or `Esc` end the editing. `Form::run(tui, skin, host)` runs over a `form::FormHost` (instead of a `render_bg` closure), a trait with `render_bg(&self, frame)` and `save(&mut self, fields) -> Result<(), FieldProblem>` - one host, because the view behind and the save usually reach the same app, which two closures cannot both borrow. `s`/`Ctrl+S` call `save` and the form stays open with the saved values as the new baseline; a second press within a second closes it. `Esc` closes an unchanged form at once and otherwise asks "Save changes?" (`y` save, `n` discard, `b`/`Esc` back). `Ctrl+O` puts the focused field back to its baseline in both modes. `FieldProblem::at(index, message)` shows in red under the field, `FieldProblem::form(message)` in a message box; nothing is saved. `FormOutcome::Saved` now means "closed after at least one save". The label column is as wide as the longest label plus two columns (instead of a fixed 14), the box as wide as its content and hint rows (instead of two thirds of the screen), an empty date shows the dimmed `enter to choose` (instead of an em dash), a choice the stepper `← value →` (instead of `‹ value ›`, whose right half was the pointer glyph), and the hint block has fixed rows - the keys of the focused field above the keys of the form - so the box keeps its height while the focus moves.
- **`form::Form` is a thin loop over the new `form::FormState`.** `Form::fields()` returns a snapshot `Vec<Field>` (instead of `&[Field]`), and `Field::is_dirty` is gone - `Form::is_dirty` answers for the whole form. A choice is drawn and stepped like a `FieldKind::Stepper`, a date is a clearable picker (`Del` empties it). `Form::state()` exposes the core for tests and hosts that want to read it.
- **`theme::Glyphs` has the new fields `mark`, `fold_closed`, `fold_open`, `stepper_left`, `stepper_right`, `descend` and `link`.** A struct literal of `Glyphs` needs them; `Glyphs::new` fills both tiers. Every glyph has one meaning: `mark` (`●`, ASCII `*`) is a ticked row of a multi-selection, `fold_closed`/`fold_open` (`▸`/`▾`, `+`/`-`) a collapsed or expanded node, the stepper (`←`/`→`, `<`/`>`) a value chosen with left/right (`Glyphs::stepper(value)`), `descend` (`»`, `>>`) a row that leads into a sub-page, `link` (`↗`, `->`) a link. `Glyphs::fold(expanded)` picks the fold marker.
- **The multi-selects mark a ticked row with `glyphs.mark` instead of the check.** `multi_select` and `multi_select_styled` lose their `check: &str` parameter and take the glyph from the skin; `multi_select_with` and the row mode of `table` use it too. The check now means only "the value that applies".
- **`modal::SelectOptions` has the new field `current`.** A struct literal needs `current: None` (or `..SelectOptions::default()`) to keep the previous behaviour.
- **`overlay::framed` returns the content rect inside the modal padding.** Every modal now keeps a blank row below its top border and two blank columns at each side (`chrome::MODAL_PADDING_TOP`, `MODAL_PADDING_X`). A host that calls `framed` and sizes its box to its content must add `chrome::MODAL_CHROME_WIDTH`/`MODAL_CHROME_HEIGHT` instead of the two border cells, or the content is cut.

### Changed

- **A list picker is as wide as its content.** `select`, `select_styled`, `select_with`, `select_reorderable` and the multi-selects size their box to the widest row (label, key and check columns, pointer and scrollbar) and their hint line, at least 34 columns, instead of half the screen.
- **`tree` and the Markdown viewer use the glyphs of the skin.** The tree's fold markers come from `glyphs.fold`, and the link line of the Markdown viewer starts with `glyphs.link` instead of the pointer glyph.
- **The toolkit modals are padded.** Confirm, message, choice, styled confirm, text and number input, the list pickers, the date, date-range and month pickers, the slider, the colour picker and the swatches grow by the padding, so their content keeps its size. The fractional overlays (finder, help, pager, Markdown viewer, table, path picker, command palette) raise their minimum size by it.
- **The help overlay ends with the modal hint block**: a blank spacer row, then the keys in the accent like every other modal (it used the dimmed accent without a spacer).
- **`form::Form` looks like the other modals.** It is drawn through `overlay::framed` (the modal fill instead of the plain background, the padding), tints the focused row from border to border with its label in the accent and bold, marks a date field with the pointer glyph, ends with the modal hint block and is at least 44 columns wide so its hint line fits.
- **The select modals mark the cursor row with the pointer glyph.** `select`, `select_styled`, `select_with`, `select_reorderable` and the multi-selects draw the pointer in a leading column on the cursor row in addition to the selection tint; every other row gets a blank column of the same width. The cursor opens on the entry that currently applies, so that entry carries both marks.

### Added

- **`form::FormState` – the non-blocking form core.** A host that runs its own event loop keeps a `FormState` in its view state, feeds it keys (`handle_key(key) -> FormEvent`) and pastes, and draws it with `render(frame, area, skin)`. It holds every rule of the style guide for a form once: normal and edit mode, focus that skips section bars and wraps, save with the form staying open and a double press closing it, "Save changes?" on `Esc` as a state of the form (`y`/`n`/`b`), the baseline with the `*` marker and `Ctrl+O`, a problem under its field (`set_error(key, message)`), a notice in the hint row, side information (`set_side_info`), a lock with its reason (`set_lock`), autocomplete suggestions, a modal sized to its content with a position badge and fixed hint rows. The fields are `FormField`s with a key and a `FieldKind`: `Text`, `Multiline` (with `Ctrl+G` for `$EDITOR`), `Toggle`, `Stepper`, `Choice`, `Picker`, `TextPicker`, `Owned`, `ReadOnly` and `Section`; `mixed()` marks a field of a bulk edit (`(mixed)`, `[-]`; giving it a value counts as a change even when the value is the one it held underneath, and `Ctrl+O` makes it mixed again), `clearable()` a picker `Del` empties, `normalized(f)` a value that compares by meaning, `max_chars(n)` a text that stops at `n` characters and shows a live `used/max` counter as its side information. A multi-line field stands beside its label, wraps there and grows with its text up to `MULTILINE_ROWS` (4) rows, with its side information in the first row. A paste on a focused text field in normal mode starts editing it. The form never opens a picker itself: `FormEvent::Activate(key)` asks the host, which calls `set_value`, or uses `FormState::choose` for a `Choice`. `FormEvent::Save` asks the host to persist `values()` and answer with `mark_saved` or `set_error`. `YES`/`NO`, `yes_no` and `is_yes` are the toggle values.
- **`form::field` – the building blocks of a form row**, for `Form` and for an app's own forms: `LABEL_GAP` (2), `MARK_WIDTH`, `PICKER_PLACEHOLDER` (`enter to choose`), `EMPTY_VALUE`, `label_column_width`, `value_column`, `label_spans`/`label_cell` (the `*` marker in its own column, the label dimmed, focused in the accent and bold, faulty in red, by `LabelMarks`), `tint_focused`/`tint_focused_lines`, `picker_value_spans` (value or placeholder, pointer glyph flush right), `with_side_info` (side information right-aligned in the field row), `problem_line` (the red line under a field) and `is_reset_key` (`Ctrl+O`). The styles come in a `FieldStyles`; `FieldStyles::from_palette` gives the toolkit look, an app with its own theme accessors fills it itself.
- **`modal::ask_save` and `modal::SaveChoice` – "Save changes?"** with `y` save, `n` discard and `b`/`Esc` back, for every form that is left with changes.
- **`SelectOptions::current` marks the entry that applies.** `select_with` opens on it and keeps the check glyph after its label while the cursor moves.
- **`reload` – `F5` reloads the configuration.** `is_reload_key`, `RELOAD_KEY` and `RELOAD_HINT`; `request(tui, skin, checked, render_bg)` shows the app's `ConfigProblems` and reloads nothing, or returns the reload `signal()` for a clean configuration, which the composition root recognises with `is_reload` and answers by building everything anew.
- **`tree::TreeView` moves without a key event**: `step`, `page`, `to_first`, `to_last`, `expand_selected`, `collapse_selected` and `toggle_selected`, so a host with remappable keys drives the tree from its own keymap. `handle_key` is built on them and behaves as before.
- **`shortcut_hints::HintStyle::footer(&skin)`** – the main-app footer style (keys in the accent and bold, labels and descriptions dim, one blank row above, no background) every app shares.
- **`chrome::fill_panel`** fills a panel of the app frame with a colour and returns its padded content area.
- **`chrome::modal_fill` returns the fill of every modal box.** `modal_block` paints it; a host box that draws its own border (in its own colour, say) takes the fill from here so it matches the toolkit modals.
- **`chrome::modal_content`** and the constants `MODAL_PADDING_X`, `MODAL_PADDING_TOP`, `MODAL_PADDING_WIDTH`, `MODAL_CHROME_WIDTH` and `MODAL_CHROME_HEIGHT` give a host box the toolkit's modal spacing.
- **`Form::set_error(index, message)`** reports a problem with a field: the next `run` shows the message in red under that field, turns its label red and focuses it; the next key clears it. The form still does not validate on its own.
- **`list::CursorMark`, `list::render_marked` and `list::render_boxed_marked` – the pointer glyph as the list cursor.** `CursorMark::Pointer` puts the skin's pointer glyph in a leading column on the cursor row (in the accent) and blanks of the same width on every other row, so the labels stay aligned; the selection tint stays. `render_marked` draws a list inside a frame it does not own (a picker popup), `render_boxed_marked` the full list box: rounded box, `position/total` badge in the bottom border, cursor marked by the given mark. `CursorMark::width` returns the columns the mark takes, for hosts that align a header row with the list. `CursorMark::Tint` is what `render`, `render_counted` and `render_boxed` keep drawing, so existing callers are unchanged.
- **`textarea::wrap_for_caret`, `textarea::CaretRows` and `textarea::row_caret` – the caret geometry of a host's own wrapped box.** `wrap_for_caret(text, width, caret)` word-wraps like `wrap_offsets` and opens one more, empty row right below the caret's row when the caret stands at the end of a row that already fills the box (the block caret is drawn after the row's last character, so it would land past the box). `CaretRows::caret_cell` gives the caret's row and display column, where a popup anchored at the caret opens. `row_caret(index, offset, len, caret, selection)` builds the `LineCaret` of one display row: the cursor column on the caret's row and the row's part of the selection. `TextArea` uses all three.
- **`TextArea::rows(width)`** – the rows the text takes at a width, the extra row of a caret at the end of a full row included, so a host can size a box that grows with its text.
- **`terminal::script_events`** queues any terminal events for a test, like `script_keys` does keys - a bracketed `Event::Paste` between keys, say.
- **`modal::hint_block`, `modal::hints_width` and `modal::HINT_BLOCK_ROWS` are public.** A host that draws its own modal ends its body with the same blank spacer and accent hint line as the toolkit modals (`hint_block`, two rows) and sizes its box so the hint line is never cut (`hints_width` plus `chrome::MODAL_CHROME_WIDTH`).

- **`editor::split_editor` is public.** It splits an editor command line (`code --wait`) into program and arguments without a shell, so a host that opens an existing file in the editor launches it the way `edit_in_editor` does.

### Fixed

- **`TextArea` keeps a caret after a full last row inside the field.** With the caret at the end of a text whose last row fills the width, the block caret was drawn one cell past the right edge (over the border of a boxed area); it now opens a row of its own below.
- **A panic is printed where it can be read.** The message went to the alternate screen, which the `Tui` guard's `Drop` then left - a crash looked like a silent exit. The first `Tui` installs a panic hook that gives the terminal back (raw mode off, alternate screen left, cursor shown) before the previous hook prints the message, the pattern of `ratatui::init`. Only a panic on the thread that holds the screen restores it; one on a worker thread leaves the running TUI alone. `Tui::for_test` installs nothing. A host that catches a panic and carries on must take the screen again with a new guard.

## [0.7.0] - 2026-11-06

### Changed (breaking)

- **`theme::Color` has the new variant `Ansi(AnsiColor)`.** A `match` over `Color` needs an `Ansi` arm. The variant names one of the sixteen terminal colours (`AnsiColor::Green`, …); `style::to_ratatui` maps it to the ratatui named colour, so it follows the terminal's palette. It has no RGB value: `rgb()` returns `None` and the OKLCH helpers (`darken`, `mix`, …) return it unchanged, like `Default` (`adjust` now returns `self` for any colour without an RGB base). `parse_color` reads `ansi:<name>` (`black`, `red`, …, `gray`, `dark_gray`, `light_red`, …, `white`; `grey` is accepted), and `to_hex` writes the same token back.
- **`ThemeColors` and `Palette` have the new colour `dim`.** It is the colour of text carrying the terminal `DIM` attribute; `Color::Default` (the value of both built-in themes and of `ThemeColors::derived`) leaves the dimming to the terminal. A struct literal of `ThemeColors` needs `dim: Color::Default` to keep the previous look. `ThemeColors::KEYS`, `ThemeColors::from_lookup` and `ColorOverrides` know the key, so a host's `[themes.*]` and colour overrides accept `dim`.
- **The Markdown default style sheet's colours** are written directly into `StyleSheet::default` instead of 33 module constants; the values are unchanged.
- **The character under an input's block cursor** takes `foreground.readable_on(cursor)` instead of a fixed black, so a light or dark cursor colour keeps it legible.
- **`StyledViews` has the new field `toggle`.** A struct literal of `StyledViews` needs `toggle: None` to keep the previous behaviour.

### Added

- **`parse_color("default")`** returns `Color::Default`, so every value `Color::to_hex` writes (a `[themes.*]` dump included) reads back.
- **`Palette::get(name)`** returns the colour a palette key names (`None` for an unknown name), for hosts that list or edit the palette by name.
- **`dim::apply_palette(&palette, amount)`** sets this thread's `DimRender` from a palette's `dim` colour (none while it is `Default`), the one call a host makes wherever it rebuilds its palette.
- **A test keeps colours in the theme** (`tests/theme_only_colours.rs`): no colour literal may appear in `src/` outside the built-in themes, the colour type, the ratatui adapter and the picker's data, each listed with its reason.
- **`dim::DimRender` and `dim::set_dim_render` – the terminal `DIM` attribute in a chosen colour.** How `DIM` looks is up to the terminal, so an app could not theme it. With a `DimRender { foreground, amount }` set (per thread, like `quit::set_confirm`), `Tui::draw` rewrites every dimmed cell of the finished frame: text in the default colour takes `foreground`, RGB text is darkened toward black by `amount` (`0.0`-`1.0`) and keeps its hue, and the attribute is removed. A named or indexed colour has no RGB base and keeps the attribute. It reaches every frame, including the modals this crate opens itself and the hint labels drawn with `style::dim()`. `None`, the default, leaves the attribute alone, so nothing changes until an app sets it.
- **`modal::choose` – a choice between a few answers shown side by side as buttons.** A `Choice` carries the frame `title`, the button `options` and the `default` button. `←`/`→`, `h`/`l` and `Tab`/`⇧Tab` move the mark and stop at either end, `Enter` returns the marked index and `Esc` cancels.
- **`modal::ToggleView` – a further view of a `confirm_styled_views` body, shown and hidden with its own key.** `StyledViews::toggle` takes a `ToggleView` with a bare `key` (e.g. `'t'`), a footer `hint` (`("t", "table")`) and a `lines` builder like the other views. The key shows the view over either of the other two and hides it again, resetting the scroll; while it shows, `←`/`→` do nothing and the `←→ view` hint is left out. The box is sized for the largest of the three views, so toggling never resizes it. `y`/`n`/`Enter`/`Esc` and scrolling work in every view.

### Fixed

- **`clipboard::copy` writes `\r\n` line endings on Windows.** A multi-line text went to the Win32 clipboard with bare `\n`, so Windows programs that split pasted rows at `\r\n` (SAP GUI, Excel) saw one cell and kept only the last line. Copy now turns every line ending into `\r\n` (an existing `\r\n` is not doubled), the counterpart of the normalising to `\n` that paste already does. macOS and Linux are unchanged.

## [0.6.0] - 2026-11-01

### Fixed

- **`editor::edit_in_editor` / `edit_in_editor_as` normalise the edited text's line endings.** The returned text was trimmed with `trim_end_matches('\n')`, so an editor configured for CRLF (Notepad, VS Code with `files.eol = "\r\n"`, `vim` with `fileformat=dos`) handed the caller back interior `\r\n` **and** a trailing lone `\r` - `"text\r\n"` trimmed to `"text\r"`. Both now collapse to LF through the existing `normalize_newlines`, which is what every other text entering an `input`/`textarea` buffer already goes through (typing inserts `'\n'`, and both the clipboard reader and bracketed paste normalise). A consuming app therefore no longer has to guess whether a `\r` can reach a buffer depending on which way the text arrived. The read/normalise/trim step is now the pure `edited_text`, so the rule is unit-tested rather than sitting behind `Command` and `Tui::suspend`.
- **`modal::confirm` / `confirm_default` and `modal::message` keep the line breaks of a multi-line text.** The confirm dialog built its prompt as a single `Line`, which drops every `\n`, and both dialogs sized their box from the width of the whole text and a fixed height. A prompt such as `"Date: …\nAmount: …"` therefore ran together into one overlong row that wrapped at an arbitrary column and pushed the `y/n` hint block out of the box. Both dialogs now take their width from the longest line and grow one row per further line (the message box keeps its previous height as the minimum), and the confirm dialog draws each line on its own row. Single-line texts render exactly as before, and the public API is unchanged.

### Added

- **`MultiSelectOptions::advance_on_tick` – tick several rows one after another in `modal::multi_select_with`.** With the option set, `Space` toggles the row and then moves the cursor to the next one, so a run of rows is ticked by pressing `Space` repeatedly; on the last row the cursor stays instead of wrapping to the top. The default (`false`) keeps the cursor where it is. `MultiSelectOptions::initial_cursor` sets the row the cursor opens on (clamped to the last row; default `0`). A struct literal that names every field of `MultiSelectOptions` needs the new fields or `..Default::default()`.
- **Every list modal shows its keys in a hint line at the bottom.** `select`, `select_styled` and `select_with` show `enter pick · esc cancel`, `select_reorderable` adds `alt+↑↓ move`, and `multi_select`, `multi_select_styled` and `multi_select_with` show `space tick · enter pick|confirm · esc cancel` – the `enter` label says whether it takes the cursor row or confirms the checks. The box grows by the two hint rows and is at least as wide as the hint line; a box too low for both keeps every row for the list and drops the hints. The mode switch of `multi_select_with` stays in the title. The signatures are unchanged.
- **`modal::confirm_styled` scrolls, and `modal::confirm_styled_views` / `StyledViews` add a second view of the body.** A body taller than the screen used to grow the box past it, cutting off the hint line; the box is now capped to the screen and the body scrolls with `↑`/`↓`, `PgUp`/`PgDn` and `Home`/`End` (clamped, with a scrollbar and a `↑↓ scroll` hint only while it overflows). `confirm_styled_views` takes a `StyledViews` – the `StyledQuestion` plus an `alternate` body builder – and switches between the two with `←`/`→` (hint `←→ view`), resetting the scroll; the box is sized for the larger of both views and for its hint line, so switching never resizes it. `StyledQuestion` and the `confirm_styled` signature are unchanged; both moved into the new crate-internal module `modal::styled`, the public paths stay `modal::StyledQuestion` and `modal::confirm_styled`.
- **`input::InputField::insertion_range` – the char range a paste would replace.** Returns the selection, or an empty range at the caret, so a caller can look at the characters around the insertion point before pasting (e.g. to add a separator only where one is missing). Read-only; nothing else changes.
- **`modal::multi_select_with`, `MultiSelectOptions` and `MultiChoice` – a multi-select with two switchable, complementary modes.** It takes the same `SelectItem`s as `select_with` (label and style; their keys are not used here). With `MultiSelectOptions::modes` set to a pair such as `["hide", "show"]`, `Tab` switches to the other mode and inverts every check, so the checks keep selecting the same items and the user edits them in whichever reading is shorter; the frame title reads `title: mode (Tab: other)`. `Enter` returns a `MultiChoice` with the checked indices (ascending) and the active mode; `Space`, the navigation keys and `Esc` work as in `multi_select_styled`. With the default options there is no `Tab` and the modal behaves like `multi_select_styled`. `multi_select` and `multi_select_styled` are unchanged.
- **`modal::select_with`, `SelectItem` and `SelectOptions` – a single-select whose entries answer to a key.** Each `SelectItem` carries its label, its style and an optional key (`SelectItem::new("Kinder").style(s).hotkey('K')`), so a key list can never be longer or shorter than the item list. A key that belongs to exactly one entry picks it at once, like `Enter` on it; a key shared by several entries moves the cursor to the next of them below the cursor, wrapping to the first, and leaves the list open for `Enter`. Letters match regardless of case; any other printable character works as well (`-` for a "none" entry); a space or a control character counts as no key, and Ctrl/Alt chords never match. As soon as one entry has a key, every row starts with a dimmed `[K] ` column (the key in upper case, blanks for an entry without one), so the labels stay aligned. `SelectOptions::vim_keys` (default `true`) keeps `j`/`k` as navigation, which then takes those two letters first; turn it off when an entry's key is `j` or `k`. With no keys and default options the modal behaves like `select_styled`. `select` and `select_styled` are unchanged.
- **`help::HelpState`, `help::render`, `help::handle_key` and `help::HelpFlow` – the help overlay without its blocking loop.** `help::show` runs its own event loop, so an app whose overlays must not block (one that drains background workers between frames) could not use it and had to hand-draw a look-alike. The new entry points split it into its parts: the host keeps a `HelpState` (query, cursor, scroll; `query()` and `paste()` on it), routes each key through `handle_key` (which reports `HelpFlow::Close` for `Esc`/`?` and leaves command chords alone) and draws with `render`, which centres and clears the same box `show` draws – dimming the view behind it stays the host's job. `show` is now built on these and behaves exactly as before.
- **`swatches::color_chooser_with`, `ChooserOptions` and `ColorChoice` – a color chooser that can remove the color and keeps a custom one.** `ChooserOptions::clearable` puts a `(none)` entry at the top of the Names and Palette lists (not while the Names list is filtered; `Enter` on it removes the color, `e` does nothing there) and makes `Backspace`/`Delete` remove the color in the list and in the picker – except in the picker's hex field, where both keys keep editing the text; a removal is reported as `ColorChoice::Cleared`. With an unset or `Color::Default` initial color the list opens on `(none)`. `ChooserOptions::picker_unless_listed` opens straight in the picker when the initial color is set but equals no named color and no palette entry exactly, so a custom value is shown as it is instead of as its nearest swatch; `Esc` there cancels and `s` still shows the list. The `(none)` entry is told apart by its name as well, since a palette entry may itself be `Color::Default`. `color_chooser` and `swatch_picker` keep their signature and behaviour.
- **`autocomplete::Autocomplete::render_popup` and `autocomplete::PopupStyle` – suggestions as a floating menu.** The inline `lines` rows push everything below them down, so a field in the middle of a form shifted the rest of the form on every keystroke. `render_popup` draws the open suggestions over the view instead: borderless, one blank column on either side, on the row below the field with its labels in the column the host passes as the value's start (the padding one column further left), flipped above the field when there is more room there, shifted left at the right edge and never outside the `bounds` the host passes (its panel or modal) – it shrinks and scrolls, or is skipped when not even one row fits. Labels are bold with the matched part plain, the highlighted row is filled across the menu, and a solid-cell scrollbar fills the right-hand column once there are more than `MAX_VISIBLE` (8) matches. `PopupStyle` holds the six colors; `PopupStyle::from_palette` derives them from a toolkit palette. Long labels are clipped with `…` by display width.
- **`modal::confirm_styled` and `modal::StyledQuestion` – a yes/no dialog with its own frame title and a caller-styled body.** `confirm` and `confirm_default` show one plain prompt under the fixed title `Confirm`; a dialog that should show *what* is about to be affected – label/value rows, a coloured warning – had no way in. `StyledQuestion` carries the frame title (usually the question itself), the `Enter` default, and `lines`: a function from the body width to the `Line`s to draw. It is a function rather than a finished list because it is called on every draw, so a body that wraps to the width follows a terminal resize; sizing and drawing ask for the same width, so the body that was measured is the body that is drawn. The box is as wide as the longest body line or the title, whichever is longer, and one row taller per further line. Keys and hint footer are those of `confirm_default`. `confirm`, `confirm_default` and `Question` are unchanged.
- **Scripted input – `script_keys` / `clear_scripted_input` / `scripted_remaining`, plus the `read_raw_event` / `poll_raw_event` seam.** `script_keys` installs a key sequence for the current thread; every reader in this crate draws from it, so a test can answer a modal instead of blocking on stdin. Thread-local rather than a global lock because the test harness runs each `#[test]` on its own thread: no locking, and no leaking between tests running in parallel. **An installed queue that runs dry is an error (`UnexpectedEof`), never a fall back to the terminal** – an under-fed test has to fail in milliseconds instead of hanging on a key nobody will press. `scripted_remaining` lets a test assert its answers were actually consumed; a leftover one means the modal never opened, which would otherwise read as a green test proving nothing. A consuming app with its own event source should read through `read_raw_event`/`poll_raw_event` rather than calling crossterm directly: the queue is shared, so a single keypress can cross the app's own loop and one of this crate's modals in the right order. Cost in a normal run: one thread-local read per event.
- **Typed date entry in the three calendar pickers.** `e` turns the centred header of `date_picker`, `date_range_picker` and `month_picker` into a text field prefilled with the current value and fully selected, so a date three years out is typed rather than walked to. The field opens in ISO – `YYYY-MM-DD`, `YYYY-MM`, `YYYY-MM-DD..YYYY-MM-DD` (the range prefills as `start..cursor` once a start is fixed) – and also takes the German forms: a day as `DD.MM.YYYY`, or as `DD.MM.` / `DD.MM` without a year, which falls in the year the field opened over; a month as `MM/YYYY` or `MM.YYYY`; a range with either kind of end, mixed, where an end without a year borrows the other end's and `20.12..5.1` runs into the next year. Day and month take one or two digits; a year takes four, read literally, or two, read as `20YY` in every form. Any other digit count, a sign or whitespace leaves the text unparseable, so a typo never lands silently in the year 26 – which is why the forms are parsed by hand in the crate-internal `date_text` rather than through chrono's `%Y`, which takes a one- to three-digit year literally. A reversed range is normalised – exactly what the calendar's second `Enter` already does. The calendar follows the typed value the moment it parses – cursor day, visible month, and both highlighted ends for the range – so `Enter` only confirms what is already on screen. While the text does not parse the field is drawn in `palette.error` and `Enter` does nothing, which is why the modal can never return a value the user did not see; an empty field is simply one of those unparseable states, so clearing stays on `Del` in the calendar. `Esc` leaves entry mode and restores the state the field opened over – for the range picker that is the cursor *and* the fixed start, since the live preview writes both – and a second `Esc` cancels the modal as before. The field is a real `InputField`, so `Ctrl+A`/`U`/`K`/`C`/`X`/`V`, `Shift`+motion, `Home`/`End` and a bracketed paste all work: the three pickers moved from `overlay::popup` to `overlay::popup_with_paste`, and their `input::is_command` guard now sits on the calendar branch alone – which is where it always belonged, since its job is keeping `Ctrl+H` from walking the day cursor, not keeping chords out of a text field. Both hint sets are padded to the taller of the two, so opening or leaving the field never resizes the box under the user's hands. The public API is unchanged.
- **`Tui::for_test(width, height)` – a terminal guard a test can actually build.** The other two constructors enable raw mode and enter the alternate screen, so a consuming app could never construct the context its key handlers take: driving a keypress in a test meant reconfiguring the developer's own terminal. The test guard renders into an in-memory `TestBackend`, runs no lifecycle hooks, and `Drop` restores nothing – restoring would disable raw mode for the whole test process and write escape sequences to the real stdout. Only terminal-free key paths can be exercised this way: a handler that opens a modal still reaches `read_event`, which blocks on real stdin regardless of the backend.
- **`date_picker::WeekColumn`, `set_week_column` and `week_column` – the switch for the calendar-week column.** `WeekColumn::Shown` (the default) or `WeekColumn::Hidden`, set once per thread like `quit::set_confirm`, so it also reaches the date picker a `form` date field opens internally. A picker reads the setting when it opens and keeps it, so its box never resizes under the user. The enum is serde-(de)serialisable as `"shown"`/`"hidden"`, so an app can take it straight from its config file.

### Changed

- **`Enter` in a multi-select with nothing checked picks the cursor row.** In `multi_select`, `multi_select_styled` and `multi_select_with`, `Enter` used to confirm exactly the checks, so moving to an entry and pressing `Enter` returned an empty set. With nothing checked it now returns the cursor row, so one entry is picked without ticking it. Once the user edited the checks (`Space`, or the inverting `Tab` of `multi_select_with`), an empty set is their choice and `Enter` confirms it, so unticking everything still clears. With checks, `Enter` confirms exactly them, as before. A caller that read an empty result as "nothing chosen" now gets the cursor row in that case. The opt-in `MultiSelectOptions::enter_picks_cursor` added earlier in this cycle is removed again: the rule is the default for every multi-select.
- **Breaking: in the swatch view `Enter` takes the focused color, and only `e` opens it in the picker.** `Enter` used to hand the color to the picker and `Space` took it directly, so the commonest action – choosing a listed color – needed the less obvious key. Now `Enter` returns the focused color (also while filtering the Names list), `e` opens it in the picker for fine-tuning (`Esc` there returns to the list as before), and `Space` is unbound. Affects `swatch_picker`, `color_chooser` and `color_chooser_with`. The swatch footer is now as tall as its wrapped hints, at least the previous two rows, so a longer hint set is never cut off.
- **Breaking: `autocomplete` keys follow blink.cmp, and every match is kept.** Nothing is preselected any more, not even with `open_on_empty`. `Tab` takes the highlighted row or else the first match; `Enter` takes only a highlighted row and is otherwise left to the caller; `Ctrl+J`/`Ctrl+K` and `Shift+Tab` move the highlight; `←`/`→` (also with `Ctrl`/`Alt`) close the suggestions and return `AcOutcome::Ignored`, so the caller still moves the caret (`→` used to accept); other `Ctrl`/`Alt` chords are ignored, so a host can pass every key through `on_key` first. A value equal to the query is now listed instead of hidden. The six-row cap is gone: all matches are kept, at most `MAX_VISIBLE` show and the rest scroll with the highlight; `lines` shows that window and its `+N more` row counts the matches outside it. The highlight now follows its candidate across a `refresh` and is dropped when that candidate stops matching – it used to stay on the same row index and so land on a different entry. The matched part is located per char with case folding, so ranges stay valid for text whose lowercase form has a different length.
- **`date_picker` and `date_range_picker` show the ISO 8601 calendar week left of each row by default.** A `Wk` column, set apart from the day grid by a separator in the border color (`│`, or `|` with `GlyphVariant::Ascii`), with the numbers in `foreground_muted`. The cursor's week is drawn in `accent` and bold, today's week halfway between `foreground_dim` and `foreground` – brighter than the other numbers, without competing with the accent; when both fall in the same row the cursor wins. The numbers are the plain ISO weeks, so the row of Monday 2025-12-29 is week 1 and the row of Friday 2027-01-01 is week 53 – what a German "KW" calendar shows, and exact for the Monday-first grid, where every row is one ISO week. Both boxes grow by five columns. Every consuming app picks this up without a code change; `set_week_column(WeekColumn::Hidden)` restores the previous calendar exactly – width, layout and hint wrapping. `month_picker` has no weeks and is unchanged. The public API is otherwise unchanged.
- **The cursor cell of all three calendar pickers is filled with the accent; today is plain accent text.** The cursor day (and the cursor month in `month_picker`, and both ends in `date_range_picker`) was drawn as accent text on `selection` – `surface` mixed only 35 % toward the accent, close to the modal background, with accent text on an accent-tinted fill – and was hard to spot. It is now filled with `accent`, bold, with the text from `Color::readable_on`, so a light theme or an accent override stays legible. Today's cell changes from `accent_dim` bold to `accent` without bold, so it reads as a marker without competing with the cursor. The days between the two ends of a range keep the `selection` tint and now read clearly against the filled ends.

### Removed

- **Breaking: `autocomplete::Autocomplete::strong_highlight`.** Its only use was a menu-style popup built from `lines`; `render_popup` replaces it.

### Internal

- `multi_select_with` lives in `modal/multi_select_with.rs` and reuses the multi-select state of `picker.rs`, now visible within `modal` (`pub(super)`), instead of a second copy of its keys.
- `select_with` lives in the new `modal/select_with.rs`, since `picker.rs` was already past 300 lines. The crate-internal `navigate_list` now maps `j`/`k` onto the arrows and hands over to `navigate_list_without_vim`, which `select_with` calls directly when `vim_keys` is off – no flag argument on the shared helper.
- `autocomplete.rs` became `autocomplete/` (`mod`, `matching`, `popup`, `inline`). The solid-cell scrollbar is the crate-internal `scroll::render_cell_scrollbar`, which shares its overflow check and thumb sizing with `render_scrollbar`.
- The week column lives in the new crate-internal `week_column` module – the setting, re-exported through `date_picker`, and the drawing both calendar pickers share. `date_picker.rs` was already past 600 lines, so the column was not added there. `weekday_header` and `day_grid` take the column as an `Option`; `None` draws exactly the previous rows.
- The typed-entry field, its `Esc` snapshot and the header-line rendering live in the new crate-internal `date_entry` module, following the `filter_list` precedent: it owns the field and the key routing without knowing what a date is, while each picker keeps only its own format, parse and preview. `date_range_picker`'s box grew one column (`BOX_WIDTH` 24 → 25) so the typed range and the block caret past its last character both fit; its header no longer overflows the inner width either.
- `Tui`'s backend is now an enum over `CrosstermBackend<Stdout>` and `TestBackend` instead of a type alias for the former. Deliberately not a type parameter on `Tui`: every consuming app takes `&mut Tui`, so `Tui<B>` would ripple a generic through each of those signatures to serve a case only tests need. The variant also *is* the fact `Drop` asks about – whether this guard ever took the screen – so no separate flag has to be kept in sync with it. `TestBackend`'s `Infallible` errors are widened into the enum's `io::Error` through an empty `match`, which proves rather than asserts that the conversion is unreachable. The public API is otherwise unchanged.

## [0.5.0] - 2026-07-19

### Added

- **`input::EditMode::Wrapped` – one logical line, soft-wrapped for display.** It navigates like `Multiline` (`Home`/`End` on the display line, `Up`/`Down` across the wrapped rows, `PageUp`/`PageDown` by the viewport height) but keeps `SingleLine`'s newline rule: `Enter` is left to the caller and a paste drops its line breaks, so the buffer never gains a `\n`. This is the mode for a field whose value is a single line by definition while being too long for one row – an expression, a query, a path. Such a field previously had to choose between wrong navigation (`SingleLine`) and a buffer that a paste could smuggle a newline into (`Multiline`).
- `fuzzy::rank_by` - the shared score/filter/sort pass behind the filter pickers. A caller supplies only how to derive each item's haystack (a `Cow`, so an item that already is its own haystack costs no copy); an empty query keeps every item in its original order. `finder`, `command_palette` and `table` previously spelled this out identically.

### Removed

- **Breaking: `keymap::KeyChord::code`.** It was added in 0.4.0 on spec and has no caller in any consuming app; `KeyChord::to_key` covers the one real need (synthesizing the press a chord matches). Since 0.4.0 is the release that introduced it, nothing that ever shipped can depend on it.

### Fixed

- **A multi-word `$EDITOR` works again.** `EDITOR="code --wait"` (likewise `subl -w`, `emacs -nw`, `vim -f`) was passed to `Command::new` whole, so the OS looked for a program whose file name contains a space, failed with `ENOENT`, and the error landed in the branch that logs a warning and returns `None` - indistinguishable from the user cancelling, with the edit silently discarded. The value is now split on whitespace into program and arguments. Deliberately not via `sh -c`, which would reintroduce the injection path.
- **`layout::centered_fraction` no longer overflows or divides by zero.** `area.width * numerator` was unchecked `u16` arithmetic on caller-supplied geometry and panicked in debug (wrapping in release) for an area wider than ~7281 columns; the fraction is now computed in `u32`. A `denominator` of zero panicked as well and is now read as "the whole area".
- **A clipboard paste on macOS/Linux now normalizes its line endings.** Only the Windows path collapsed `\r\n` and lone `\r` to `\n`, although its doc claimed the shape was uniform; text copied out of a Windows VM, a CRLF editor or a browser text area therefore reached a field through `pbpaste`/`xclip` with stray `\r` control characters. Both paths and `terminal`'s bracketed-paste seam now share one normalizer. Its tests were `#[cfg(all(test, windows))]` and so never ran on the development machine; they are platform-independent now.

### Security

- **`path_picker` no longer hands out a path that leaves the confinement root.** `PathPickerConfig::root` was enforced while *navigating* - `descend` canonicalizes so a symlinked folder cannot be entered - but `Enter` returned the selected entry's path unresolved and unchecked. A symlink inside the root pointing anywhere outside it was therefore listed, selectable, and delivered verbatim to the caller, which is the one code path that produces a value. `Enter` now canonicalizes the selection and rejects it unless it lies within the root; unlike the navigation fallback, a path that cannot be resolved is refused rather than passed through.
- **`opener::open` no longer goes through `cmd.exe` on Windows.** It ran `cmd /C start`, which is a shell: Rust escapes arguments for the CRT `argv` convention, not for `cmd`'s own handling of `&`, `|`, `^` and `%VAR%`, so a file name carrying one of those could break out (the class of CVE-2024-24576). It now uses `rundll32 url.dll,FileProtocolHandler`, which takes the path as a single argument with no shell involved. This makes the module's long-standing "never a shell" documentation true on every platform.
- **A path is no longer mistaken for an option by the platform opener.** `open`/`xdg-open` parse their arguments, so a *relative* path to a file named e.g. `-a` arrived as a flag (`open -a` even swallows the next token as an application name). `opener::open` now makes the path absolute first, which closes this on every platform without depending on a `--` separator that not all `xdg-open` implementations honour.

### Internal

- **Thirteen modules are split into child modules along responsibility lines**, following the pattern `table/` already used: the type stays in `mod.rs` and its methods move into sibling `impl` blocks. `input` (1179 non-test lines, now 28), `markdown/render`, `modal` (six unrelated widget families in one file, now one per family), `swatches`, `keymap`, `color_picker`, `sidebar` (a 22-method impl, now four), `theme::color` (19 methods), `form`, `path_picker`, `command_palette`, `shortcut_hints` and `textarea`. **The module paths and every public item are unchanged** - `clibase` builds and tests against this without a single edit, which is what makes the claim checkable.
- **`filter_list::FilterList`** now carries the query buffer, cursor, scroll state and the whole navigation/typing key dispatch shared by `finder`, `help` and `command_palette`. The three were near-verbatim copies of it - including the `Ctrl` guard and the `Tab` section jump - so a fix reached at most one of them. Their public signatures are unchanged.
- `markdown/theme.rs` no longer holds 34 raw `ratatui::style::Color::Rgb` literals. Its palette is declared in `theme::Color` and mapped through `style::to_ratatui`, restoring the invariant that `style.rs` is the single seam. The rendered colours are identical, pinned by a test asserting literal RGB values.
- **The 0.4.0 key-handling rules are now pinned by tests.** Every Ctrl guard, the `AltGr`-must-type rule of each filter buffer, `is_bare_character`'s `Alt` clause, `is_global_quit`, and `keymap::Action::overlaps` now have a test that fails if the behaviour is reverted. Several were previously provable only by reading the code - and one, `is_bare_character`'s `Alt` clause, could be deleted with every doctest still green.

## [0.4.0] - 2026-07-17

### Added

- **`keymap` – user-remappable key bindings, the shared chord layer.** An app implements `keymap::Action` for its own action enum (`all`/`config_name`/`description`/`default_keys`, plus an optional `overlaps` for scoped actions and a defaulted `from_config_name`) and gets:
  - `KeyChord` – `parse` (`"ctrl+s"`, `"shift+left"`, `"pgup"`, `"G"`), `matches`, `display`, plus `from_key`/`to_key` to convert to and from a live `KeyEvent`, and `code` (removed again after this release, see Unreleased).
  - `Keymap<A>` – `from_overrides` (every action), `for_actions` (a subset, for an app that builds one map per view), `action_for`, `action_for_where` (a filtered lookup for scoped actions), `keys_for`, `hints` (`(keys, description)` pairs for a footer), `conflicts`, and `Default`.
  - `Conflict<A>`, the `KeyBinding` serde enum (`key = "ctrl+s"` and `key = ["ctrl+s", "f2"]` both deserialize) and `warn_unknown`.

  This replaces the ~285 lines of chord machinery each consuming app had copied; the action table stays in the app, the chord grammar lives here once. `KeyChord::matches` compares `ctrl`/`alt` **exactly**, never with `contains`, which is what keeps `AltGr` (reported as `Control + Alt`) from triggering a `ctrl+…` binding. `Action::all` returns an iterator rather than a slice, because an app's actions are typically one column of a catalog table and a `&'static [Self]` would force a second, redundant list. The grammar also gained `backtab` and `insert`, which the hints renderer knew but the chord parser did not.
- `input::is_bare_character` – the counterpart of `input::is_command`: whether a key is a plain typed character (`Char(_)` without Control or Alt). Stricter than `!is_command`, because it also excludes `AltGr`. A widget matching a plain letter (`y` to confirm, `j` to move) gates on this; a widget filling a **text buffer** keeps using `!is_command`, since `AltGr` must type there.

### Changed

- **Breaking (behaviour, not signature): `shift` is significant for non-character keys.** In `keymap::KeyChord`, `left` matches `Left` *without* Shift, and `shift+left` is a separate chord an app can bind. A character key is unaffected: its Shift lives in the case (`G`, not `shift+g`) and is not compared. An app that relied on a bare arrow chord also firing on `Shift`+arrow must bind `shift+…` explicitly - which is the point, since it removes the need to handle `Shift`+arrow beside the keymap.
- **One rendering of a key.** `shortcut_hints`' private `chord_label`/`key_label` now render through `keymap::KeyChord::display`, so a footer hint, a config `[keys]` entry and the chord a handler matches on are the same text, and it round-trips through `KeyChord::parse`. This changes three tokens (`delete` → `del`, `pageup`/`pagedown` → `pgup`/`pgdn`) and, deliberately, **stops lower-casing a character**: an app binding both `g` and `G` used to show one footer token for two actions. `global_bindings()` still returns `String`s.

### Fixed

- **A Ctrl chord no longer triggers a widget's plain-key action.** Every key handler matched on `key.code` while ignoring the modifiers, so - in raw mode, where crossterm reports `Ctrl+J`/`Ctrl+H` as `Char('j')`/`Char('h')` plus CONTROL - a chord fired the bare binding. Most severe: **`Ctrl+Y` silently confirmed a `modal::confirm`**, defeating `Question::declining` on a destructive prompt (`AltGr+Y` did too). Also fixed in `modal`'s list navigation and multi-select, `table` (`Ctrl+S` re-sorted, colliding with `form`'s `Ctrl+S` = save), `tree`, `sidebar`, `pager` (`Ctrl+N` jumped to the next match), `swatches` and `color_picker` (`Ctrl+Y` copied, `Ctrl+S` switched view), the three date pickers, `slider`, `markdown::view` (`Ctrl+O` opened a link) and `form`'s checkbox.
- **A Ctrl chord is no longer typed into a filter or search buffer** as its plain letter, so `Ctrl+U` clears the line instead of inserting a `u` (`command_palette`, `finder`, `help`, `pager`, `sidebar`, `table`, `swatches`). `AltGr` characters (`@`, `\`, `[`, `~`) still reach those buffers, as they always must.
- `terminal`'s global quit and `path_picker`'s `Ctrl+H` now test `input::is_command` rather than a bare `CONTROL` check, so `AltGr` cannot reach them. Neither was reachable in practice - no German `AltGr` glyph collides with `q` or `h` - but the rule no longer depends on that.

Hiding the hints reclaims their rows, the blank spacer above them included, so widget boxes shrink to fit. New: `shortcut_hints::{visible, set_visible, toggle, footer_height, default_toggle_key, toggle_key, set_toggle_key, global_bindings}`. The chord is rebindable, and unbinding it with `set_toggle_key(None)` hands the key back to the host. `global_bindings` yields the chords the toolkit itself intercepts – the toggle (named after its current binding) and the hard `Ctrl+Q` – for a host to splice into its footer and help overlay; with the hints hidden the toggle is nowhere else to be seen.
- `shortcut_hints::consume_toggle` is now public, so an app that drives its own event loop instead of `driver::run` can inherit the hints toggle with one line at the top of its key dispatch, rather than matching the chord by hand.
- `quit` – an opt-in confirmation before quitting. `quit::set_confirm` picks whether the hard `Ctrl+Q`, the host's own quit action, both or neither are questioned (neither, by default); `quit::set_guard` registers how the dialog is drawn. `run` and `popup` ask for the hard chord themselves; a host calls `quit::request` in its own quit action, which is the only place that knows where that quit came from.
- `input::query_spans` and `InputField::caret_spans` – a text line with a block caret and no field background, scrolling horizontally to keep the caret in view. The single source every filter/search line now draws its caret with.

### Changed

- **Breaking:** `ThemeColors` gained a `border_focus` field. Every struct literal has to name it; `ThemeColors::derived`, `from_accent` and `from_lookup` fill it on their own. Hosts building a theme from a color table are unaffected.
- The `position/total` indicator now always sits in a frame's bottom border (`─ 3/12 ─╯`) instead of floating over the last list row, and is drawn in the new, dimmer `foreground_muted`. Popups over a scrollable list – `path_picker`, `finder`, `command_palette`, `help`, `swatches`, `modal::select`, `modal::multi_select` and the `table` modal – gained one; `form` gained a focused-field counter. A frame too narrow for the badge drops it rather than overwriting a corner.
- `pager` and the `markdown` viewer show their scroll percentage in the bottom border; the pager's footer no longer repeats it.
- A boxed `table`'s badge now reads `12/80` (cursor position and row count) instead of the bare row count. Its status line is unchanged.
- `shortcut_hints::height` returns `0` while the hints are hidden (previously at least `1`), and `lines`/`group_lines` return an empty `Vec`, so a host that budgets its footer with `height` reclaims the top margin along with the hints.
- Filter and search lines (`finder`, `command_palette`, `help`, `swatches`, `sidebar`, `table`, `pager`) scroll horizontally and mark a scrolled-off head with `…`, instead of being cut off at the line end. They share one caret renderer rather than each rebuilding the caret span inline.
- Modal frames now fill with a slightly lightened background, lifting the box above the dimmed backdrop so it reads as an elevated surface.
- Form and toast frames now title via the shared `chrome::border_title`, so their leading `─` connector takes the border color (matching modals) instead of the title/accent color.
- `modal::number_input` now falls back to the initial value instead of `0` when the entered text cannot be parsed as an integer.
- `textarea` wraps **word-aware**: a soft break falls on the last space that fits and consumes it, instead of hard-splitting mid-word at the column. A word longer than the width is still hard-split. `TextArea::render` and the new `wrap_offsets` share the one implementation.

### Removed

- The overlay `position/total` chip `list::render` used to draw over its last row. Plain `list::render` no longer shows a count; use `list::render_counted` (a reserved bottom row), `list::render_boxed` with a `BoxDecor`, or let the surrounding popup frame carry the badge.

### Fixed

- A `toast` box grows to its message. Every box was drawn three rows tall ("border + one wrapped line"), so anything longer than the inner width was cut off after the first line - the message wrapped, but the rows were not there. `render` now measures the message with `text::wrap` and sizes the box to it, capped at six lines with a trailing `…`. The wrapped lines are handed to the `Paragraph` directly instead of re-wrapping them with `Wrap`, so measuring and drawing cannot disagree.
- A caret line no longer overflows its width. With both a head and a tail `…` marker, a window of two columns drew three: the markers were taken before the text was given a column. Markers are now dropped, tail first, until the text and its block caret keep at least one column (`input::caret_spans`).
- `AltGr` characters are typed again instead of being swallowed as command chords. `input::apply_edit_key` and `textarea::TextArea::handle_key` tested `KeyModifiers::CONTROL` alone, but crossterm reports `AltGr` as `Control + Alt` – so on a German keyboard `\ @ [ ] { } | ~` never reached the buffer. Both now go through the new `input::is_command` (`Control` *without* `Alt`), which is public so hosts with their own key dispatch can share it.
- Opening a popup in a terminal narrower or shorter than the popup's preferred minimum panicked with `assertion failed: min <= max`. `modal::confirm`, `message`, the list pickers, `input_wide`, `command_palette` and `layout::centered_fraction` reached `Ord::clamp(min, max)` with `max < min`. They now use `layout::fit`, where the available space wins over the preferred minimum. A `confirm` dialog in a 20x6 terminal used to crash the host application.
- `path_picker` shows the block caret in its filter line again. The field is a full `InputField`, but the render path drew only its value, so nothing marked where typing would insert – including on an empty filter.
- The hints toggle compared only the key code, so `Shift+F1` toggled the hints as well. Modifiers are now matched exactly.
- An unboxed `tree` shows its `position/total` counter again. It had vanished with the overlay chip, since a frameless widget had nowhere to put one.

## [0.2.0] - 2026-07-07

### Added

- `markdown` module: a CommonMark renderer (headings, lists, task lists, code blocks, blockquotes, GFM tables and callouts, links, plus a `==highlight==` extension) that produces styled `ratatui` lines. Includes a themeable `StyleSheet` (`Default` plus `StyleSheet::from_skin`), a scrollable `MarkdownView` widget with link navigation, and a blocking `viewer` modal. Backed by the new `pulldown-cmark` dependency.
- `text::wrap` – unicode-width-aware word wrapping (hard-splits over-long words).
- `log` diagnostics for degraded conditions (`warn`/`error`): a failed terminal restore on exit, a missing clipboard tool, an unreadable directory, a `canonicalize` fallback that weakens path confinement, an invalid color override, and an unknown theme name.

### Changed

- Complete rustdoc coverage, enforced crate-wide with `#![warn(missing_docs)]`.

## [0.1.0] - 2026-07-02

Crate-wide cleanup and API consolidation. This release contains breaking changes.

### Changed

- Grouped scroll parameters into `nav::ScrollView` (used by `scroll::render_scrollbar`/`render_hscrollbar` and `nav::keep_visible`) and list parameters into `list::ListView` (`list::render`/`render_boxed`).
- `path_picker::path_picker` now takes a `PathPickerConfig` with an optional `root` that confines navigation (checked via `canonicalize` + `starts_with`).
- Renamed the crate-root command-palette module `palette` → `command_palette` (`PaletteItem` → `CommandItem`), ending the name clash with `theme::palette`.
- Split the `table` widget into a `table/` submodule (model / interaction / render); behavior unchanged.
- `textarea` now reuses the shared single-line edit core from `input` (SSOT).
- Documentation synced with the code and the public API surface tightened.
